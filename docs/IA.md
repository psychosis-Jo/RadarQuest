## 0. 一句话定位

**「抓过来 → 决定留 → 去做 → 沉淀」** 4 步 funnel，对应 4 个 tab。

不是 productivity 工作台，是「**夜空下的小航海日志**」——你每天扫一眼捕捉到的东西，留几颗星在云上，然后真的去产出几件作品。

---

## 1. 4 步 funnel

```
┌──────────┐    保留     ┌──────────┐    5 动作     ┌──────────┐
│  捕捉    │ ──────────→ │   星云   │ ──────────→ │   我的    │
│ (外部世界)│   决定要不要 │  (你的云) │  真的去做了 │  (沉淀)  │
│          │             │          │             │          │
│ ·未处理卡片│             │ ·已留的星 │             │ ·等级 XP  │
│ ·按主题聚合│             │ ·按 topic 簇 │             │ ·任务进度│
│ ·快速决策  │             │ ·在做的事  │             │ ·星座进度│
└──────────┘             └──────────┘             └──────────┘
  /capture                 /                       /my
```

| 步骤 | 页面 | 状态机 | 元素 |
|------|------|--------|------|
| 1. 外部世界 | **捕捉** | `unprocessed` | 主题聚合的卡片流 |
| 2. 你的云 | **星云**（主页） | `kept` | SVG 星辰（按 topic 簇） |
| 3. 沉淀 | **我的** | `archived` | 数字面板 + 子页签 |
| | **设置** | — | 关键词 / 信源 / 强度 / 音效 |

数据**单向流**：抓取 → 捕捉 → 保留（手动） → 星云 → 动作 → 推进 我的。

> **不会有"反向回流"**。星云的星不会回捕捉，已完成的 Boss 不会回活跃。删除是软删（30 天可恢复），不重建 funnel。

## 4. 捕捉页（`/capture`）—— 主题聚合卡片流

**为什么不要 5-Tab**：5-Tab（Trending/Spike/Rise/Density/Cross）原本是按"热度维度"分桶，但 StarCatcher 的核心是 **topic**（AI / 一人公司 / 自我管理），不是热度分类。维度分裂会让用户在三屏之间跳；topic 聚合更直接——"我今天关心 AI 方向，看 AI 区就行"。

**页面结构**：

```
┌──────────────────────────────────────────────────────┐
│  捕捉 · 今日                                          │
│  共 N 条新信息 · 4 个主题                              │
│  ─────────────────────────────────────────────        │
│                                                      │
│  ## AI 应用  ····· 12 条   [展开/收起]                 │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐         │
│  │ Card 1 │ │ Card 2 │ │ Card 3 │ │ Card 4 │         │
│  └────────┘ └────────┘ └────────┘ └────────┘         │
│  ┌────────┐ ┌────────┐ ...                            │
│                                                      │
│  ## 一人公司  ····· 5 条    [展开/收起]                 │
│  ┌────────┐ ┌────────┐ ...                            │
│                                                      │
│  ## 自我管理  ····· 8 条   [展开/收起]                 │
│  ┌────────┐ ...                                      │
│                                                      │
│  ## 未分类  ····· 3 条     [展开/收起]                 │
│                                                      │
│  ─────────────────────────────────────────────        │
│  已保留 · 7 条                          [查看全部 ▾]   │
│  ┌────────┐ ┌────────┐ ...                            │
└──────────────────────────────────────────────────────┘
```

**Topic 排序**：按数量降序（AI 12 > 一人公司 5 > 自我管理 8 > 未分类 3）—— 最多的话题排最上，让用户先看自己最关注的。

**卡片元素**（DESIGN §8 的 ItemCard 复用）：
- source logo + 标题（Fraunces 20px）
- 摘要（Inter 15px，2 行截断）
- 5 动作 + meta（👀 7 🔖 12 ... 5h ago · GH）
- **Triage 行**：`[✅ 保留] [⭐ 收藏] [❌ 忽略]`

**Triage 行为**（per 用户回答 IA 问题）：

| 动作 | 数据状态 | UI 反馈 | 后续 |
|------|---------|---------|------|
| **✅ 保留** | `state: kept` | 卡片沉到页面底部"已保留"区（带"已保留"角标），原位置消失 | item 出现在星云（主页） |
| **⭐ 收藏** | `state: kept + saved` | 立即从捕捉页消失（收藏是更强的保留） | item 出现在星云 + 收藏角标 |
| **❌ 忽略** | `state: dismissed` | 卡片淡出消失 | 30 天后硬删；30 天内若该 item 再次 spike 重新召回（DESIGN §5.3） |

> **关键**：保留后**不立刻从捕捉页消失**（避免"咔嚓一下什么反馈都没有"），而是**沉到"已保留"区**（per 用户选择 C）。这个"已保留"区相当于一个微 funnel 可视化——用户能直观看到"今天留了 7 条"。

**空状态**：
- 0 条新信息：`"今晚海面平静，暂无新信息"`（用古星图册语气）
- 全部已处理：所有 section 折叠，只显示"已保留"区，提示"今日 7 条已决定"

**"已保留"区**：
- 始终在页面底部
- 按保留时间倒序
- 数量 >10 时折叠，需点"查看全部"展开
- 每个卡片显示保留时间（"3 分钟前保留"）

## 5. 星云（`/`）—— 主页

不变。已实现 force-directed SVG 星辰布局。

**职责**：展示**已留下**的星，每颗星是一段决定要处理的信息。点击星在星旁弹出详情卡（v1.3 起，原 Drawer），做 5 动作（看/收/写/做/发），星随 XP 变亮变大。

**前置条件**：从 `/capture` "保留" 过的 item 才会出现在这里。

```
│  · 猎户座 4/7 50%    · 看了 3              │
│  · 天鹅座 2/5 40%    · 收藏 1              │
│                       · 写笔记 1            │
│                                             │
│  快速入口                                    │
│  [任务]  [技能]  [星座]  [星图册]  [设置]   │
└─────────────────────────────────────────────┘
```

**子页签**（点击上方快速入口 / 子路由进入）：
- `/my/quests` —— 任务列表（QuestManager 移入）
- `/my/skills` —— 三主题技能树（Sidebar 里的内容移入）
- `/my/bosses` —— 活跃 / 已完成 / 放弃 三个 section（BossManager 移入）
- `/my/sky-atlas` —— 已完成星座册（DESIGN §7，独立页）
- `/settings` —— 设置（SettingsForm 移入）

**子页签之间不嵌套**：每个子页签是完整页面，从 `/my` 进。子页签间通过 `/my` 内的"快速入口"互联。

## 7. 设置（`/settings`）—— 独立 nav

**为什么不在 `/my` 内**：设置是**低频高门槛**（关键词、信源、强度档位），不是日常操作。放 header 独立 nav 更直接。

**设置页结构**（DESIGN §12 + SettingsForm 已实现）：
- 强度档位（5 档，纯数据 → 全力冲刺）
- 独立开关（音效 / 动效 / 每日任务数）
- 关键词（3 个 topic 各一组，CRUD）
- 信源（6 个平台启用 / 禁用，list 类源可加 feed）
- 恢复默认

**Header 设置入口** → 跳 `/settings`（已在主 nav 4 项里，不再单独齿轮）。

```
       │          抓取 (GitHub Actions)         │
       │   pnpm fetch → Supabase items 表      │

       └──────────────────┬───────────────────┘
                          │

       │        /capture · 主题聚合卡片         │

       │   收藏 (⭐) → 立即消失                │
       │   忽略 (❌) → 淡出消失                │
       └──────────────────┬───────────────────┘
                          │ 保留 / 收藏
                          ▼
       ┌──────────────────────────────────────┐
       │            /  · 星云主页              │
       │   state = 'kept' 出现在 force 布局     │
       │   点击星 → 弹出详情卡 → 5 动作       │
       │   动作 → state='archived' 隐到星云深处  │
       │           + actions 表加记录           │
       └──────────────────┬───────────────────┘
                          │ 5 动作
                          ▼
       ┌──────────────────────────────────────┐
       │             /my · 沉淀               │
       │   Level / XP / Streak                  │
       │   /my/quests  任务进度                 │

       └──────────────────────────────────────┘
```

**关键不变量**：
- 捕捉 ↔ 星云 ↔ 我的 是**单向 funnel**
- 删除 / 忽略 ≠ 真删，30 天软删可召回（DESIGN §5.3）
- 设置只影响"抓取"和"显示"，不影响 funnel 方向
