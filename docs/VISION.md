# VISION

> 数据是死的，作品是活的。这整个工具的使命，是把前者变成后者。

## 一句话定义

**Radar Quest 是一个让"看到热点"这件事最终能变成"产出一个作品"的个人技术雷达。**

## 为什么存在

现在所有的"热点追踪工具"——GitHub Trending、Product Hunt、Hacker News、各种 newsletter——都在**做好第一步：让你看到**。

但看到之后呢？

绝大多数时候，看完就忘。收藏夹是坟场。Notion 里"以后再看"的列表永远不会再看。

问题不在热点不够，而在于：
- 看完一条 GitHub 仓库，没有一个轻量的动作能让我"先记一下为什么值得关注"
- 写了一句笔记之后，没有一个回路能把它导向"我下一篇公众号文章"
- 写公众号文章的时候，已经忘了 3 个月前看到的一个新框架

**Radar Quest 要解决的就是"从看到到做到"这条断掉的链路。**

## "星图"哲学

整个产品的视觉语言围绕一个比喻：

> **Radar = 仰望星图，搜寻信号**
> **Quest = 一段旅程，从发现到产出**
> **Starlight = 每次产出 = 点亮一颗星**

具体来说：
- 你注册进来时，是一片**空白的夜空**
- 每次 Watch（扫一眼）= 一颗暗淡的白色小点
- 每次 Save（收藏）= 稍亮一些
- 每次 Note（写笔记）= 淡黄
- 每次 Build（动手做）= 暖橙
- 每次 Publish（产出）= **一颗蓝白的光星，带着光晕**
- 每次 Boss 击破 = 一组新的星座亮起
- 三条技能树 = 三片**已经命名的星座**（AI / 一人公司 / 自我管理）

慢慢积累，你的 dashboard 主页会呈现一片属于你自己的夜空。每一个光点都是一次你从"看到"到"做出"的真实行动。

**这不是装饰。这是把你的创作轨迹具象化。**

## 我们要做什么

- **抓**：从多个信源聚合热点（GitHub / PH / HN / Reddit / Newsletter / 公众号）
- **看**：5 个维度的榜（Trending / 短时间爆发 / 持续上升 / 讨论密度 / 跨平台提及）
- **做**：每条热点都能变成 5 个层级的动作（Watch → Save → Note → Build → Publish）
- **追**：双 streak（行动 streak / 输出 streak）+ 成就
- **战**：可自定义的 Boss 关卡（比如"100 个 AI 作品"）
- **看**：你自己的星图主页，把过去 30 天的行动与产出变成夜空

## 我们不做什么

- **不**做信息流。Radar Quest 不是让你刷的，是让你"做"的
- **不**做 social。看别人 Boss 进度、评论、关注——v1 不做。**这是你的私人创作引擎，不是社区**
- **不**做 AI 摘要 / AI 聚类。这些是 v2。v1 只做"信号归集"和"动作闭环"
- **不**做"今日必看"。我们尊重你的判断，不替你的注意力做主
- **不**用积分衡量你的价值。**积分是动作的影子，不是目标**

## 目标用户

写公众号、做独立产品、保持技术敏感度的一人公司 / 独立开发者。
有自己的长期创作项目（比如"100 个 AI 作品"），需要一个外部系统来"温柔地推"自己。

## 设计原则

1. **行动即奖励**。XP / Level / 徽章是影子，真正有重量的是 Publish
2. **浪漫胜过冷感**。星图、墨水笔、风铃、远洋钟声。我们在做工具，也在讲故事
3. **数据主权在你**。所有动作记录、笔记、输出关联都可导出 JSON / Markdown
4. **可关闭的温柔**。游戏化默认开，但**任何一档都能关掉**。工具是为你服务，不是反过来

## 终极检验

Radar Quest 成功的标志不是"用户每天打开"，而是：

> **"我 6 个月前看到的一个 GitHub 仓库，因为 Radar Quest 的提醒，真的变成了我的一篇公众号文章。"**

或：

> **"我点开了 100 个星图上的星点，写了 100 篇公众号文章，做完了 100 个 AI 作品。"**

这是我们要走到的终点。
